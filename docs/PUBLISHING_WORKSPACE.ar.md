# تشغيل مساحة النشر المطورة

الدفع ما زال مؤجلًا. هذه الإضافات لا ترسل حملات خارجية ولا تجري تحصيلًا ماليًا.

## الصفحات

- `/app/publishing`: الكتاب والفصول والغلاف والمنتج والنسخ والأسعار والملفات والمراجعة.
- `/app/publishing-operations`: مهام من السجلات الفعلية، وتنبيهات الخدمات وأخطاء الواجهات.
- `/app/reading-reports`: تقارير القراءة حسب الفترة والمنصة والكتاب والمؤلف، وتصدير CSV.
- `/app/reader-360`: العميل وطلباته واشتراكاته ودعمه والقراءة المشتركة للتحليل.
- `/app/publishing-staff`: أدوار الموظفين وسجل الطلبات الإدارية ونتائجها.

## الكتاب من التحرير للنشر

1. أنشئ كتابًا واختر المنصة الصحيحة. يمكن حفظ مسودة ناقصة.
2. أضف الفصول ورتبها، ثم الغلاف والوصف والمؤلف. المعاينة داخل الإدارة تعرض المسودة فقط.
3. اختياريًا: اربط منتج Medusa أو أنشئ منتجًا كمسودة. راجع أسعار النسخ بالعملة الأساسية، والمخزون والشحن للنسخ المادية.
4. ارفع الملفات الخاصة من تبويب الملفات، واربط كل ملف بالنسخة المناسبة، ثم احفظ بيانات الملفات. هذه العملية مستقلة عن حفظ نص الكتاب وتعرض نتيجتها منفصلة.
5. أرسل المسودة للمراجعة. لا يمكن تعديل نسخة قيد المراجعة أو معتمدة دون إعادتها للتحرير.
6. مسؤول النشر يعتمدها ثم ينشرها بتأكيد واضح. المنتج المرتبط يجب أن يكون منشورًا ومتوافقًا مع منصة الكتاب.
7. تعديل كتاب منشور أو استعادة نسخة قديمة ينشئ مسودة؛ القراءة العامة تظل على النسخة المنشورة السابقة. الأرشفة تخفي القراءة العامة.

كل حفظ أو إجراء يتحقق من رقم النسخة. عند تعارض محررين، أعد تحميل الكتاب ثم راجع التغييرات؛ لا تتجاوز التعارض بتغيير الرقم يدويًا. الاستعادة تحتاج سببًا وتُنشئ رقم نسخة جديدًا.

واجهة `reading-stories` القديمة باقية للتوافق. مدير النظام وحده يستطيع النشر المباشر منها؛ تُسجل العملية في سجل النسخ والإجراءات. استخدم مساحة النشر الجديدة للعمل اليومي.

## الموظفون

اضبط `ADMIN_EMAIL` على بريد مالك التثبيت الموجود فعلًا. إن لم يُضبط، يُختار أقدم حساب إدارة فعّال لتهيئة دور المدير. الموظفون الآخرون يبدأون كمحررين. التعيين مخزن في قاعدة البيانات ويُفحص مع كل طلب، حتى لو كانت جلسة الموظف مفتوحة قبل تغيير دوره.

| الدور | الصلاحيات الأساسية |
| --- | --- |
| مدير النظام | كل الأقسام، الموظفون وسجل الإجراءات |
| مسؤول النشر | تحرير ومراجعة ونشر، منتجات وأسعار وملفات، تقارير |
| محرر | محتوى ومسودات وملفات خاصة لمنتجات غير منشورة، دون اعتماد أو نشر أو تغيير أسعار |
| الدعم | عملاء ودعم وقراءة الطلبات وتعديل المسودات التجارية |
| المخزن | مخزون وشحن وقراءة الطلبات |
| محلل | تقارير وقراءة الكتالوج |

إخفاء أزرار الواجهة ليس الحماية الأساسية؛ الخادم يرفض العمليات غير المسموحة. لا يمكن خفض صلاحية آخر مدير أو حذف مدير قبل نقل دوره. سجل الإجراءات يحفظ المنفذ والدور والمسار والنتيجة، ولا يحفظ كلمات المرور أو نص الملاحظات الخاصة.

رفع الغلاف العام، وإتاحة عينة مجانية، وتعديل ملفات منتج منشور أو بيانات ملفات يشترك فيها منتج منشور تحتاج مسؤول نشر أو مديرًا. المحرر يستطيع تجهيز الملفات الخاصة للمسودة. نسخ الكتاب تحفظ المحتوى التحريري؛ الأسعار وملفات المنتج تُحفظ بعمليات Medusa مستقلة ولا تدخل في استعادة النص.

## مزامنة القراءة والأسرة

- تسجيل الدخول يربط المفضلة والموضع والملاحظات والتفضيلات بالحساب. بيانات تنزيل الملفات تبقى خاصة بالجهاز.
- أثناء جلسة قراءة سبق تحميلها، الحفظ المحلي يظل متاحًا دون اتصال وتُرسل التعديلات عند عودة الشبكة. فتح جلسة حساب جديدة يحتاج اتصالًا. الحقول المختلفة تُدمج؛ تعديل الحقل نفسه يأخذ أحدث توقيت مقبول. مسح سجل منصة يمسح حتى الكتب غير المحملة بالجهاز ويمنع عودتها من نسخة قديمة، مع إبقاء المفضلة.
- قراءة الزائر لا تنتقل تلقائيًا للحساب. زر الاستيراد في تفضيلات القراءة ينقلها باختيار صاحب الحساب.
- ملفات الأسرة على الحساب تعزل القراءة حسب الملف والمنصة. فتح إدارة الأسرة يتطلب كلمة مرور الحساب ويمنح ملف ارتباط HttpOnly لعشر دقائق. هذا لا يُعد إثباتًا قانونيًا للوصاية.
- اختيار المشاركة في التحليل اختياري؛ إيقافه يحذف أحداث التحليل لذلك الملف ويُبقي القراءة الخاصة. تغيير اختيار طفل يحتاج إعادة التحقق من صاحب الحساب.
- التقارير تعرض أحداثًا فعلية بعد الاختيار فقط؛ استيراد السجل الأول ليس نشاطًا جديدًا. لا توجد ادعاءات بمدة استماع أو نسبة إكمال حقيقية لكتاب لم تُقَس.
- التوصيات محلية المنطق في الخادم، مبنية على أنواع الكتب المحفوظة والمكتملة، ومقيدة بمنصة القراءة، دون خدمات ذكاء اصطناعي خارجية.
- حذف العميل من Medusa يمسح حالة القراءة وملفات الأسرة وأحداثها ورموز إعادة التحقق من الخادم ويرفض بيانات دخوله القديمة. النسخ المحلية المنزلة على أجهزة منفصلة تحتاج إدارتها على تلك الأجهزة.

## الملفات والتنبيهات

الملفات حتى 32 MiB تستخدم الرفع المباشر مع تقدم فعلي. الأكبر تُرفع بأجزاء 8 MiB حتى 2 GiB. يمكن إيقافها مؤقتًا واختيار نفس الملف خلال 24 ساعة؛ تُراجع بصمة كل جزء محفوظ قبل تجاوزه. تغيير محتوى جزء سابق يرفض الاستئناف. الصيغ المقبولة PDF وEPUB وMP3 وM4B/M4A وWAV، مع فحص ترويسة المحتوى؛ هذا ليس فحص برمجيات ضارة أو DRM تجاريًا.

التخزين خاص وروابط المعاينة تنتهي خلال دقيقة. لا تنقلها إلى محتوى عام. الفحص الدوري كل خمس دقائق يراجع الكاش وحاوية التخزين وعينة من الملفات، وينظف الرفع المنتهي. ليس ضمانًا أن كل ملف يُفحص في كل دورة. تنبيهات الواجهات محدودة المعدل وتُحجب منها الأسرار الشائعة. تأكيد الاطلاع منفصل عن تحديد التنبيه كمعالج؛ عودة العطل تعيد فتحه.

## التثبيت والتحديث

اتبع دليل التشغيل الأساسي `OPERATIONS.md` وأدلة النشر داخل `docs/`. المستودع يحمل الكود، لكنه لا يحمل قاعدة بياناتك أو الملفات أو الأسرار. خذ نسخة قاعدة البيانات والتخزين والأغلفة والأسرار قبل النقل أو التحديث. الإضافات تنشئ جداولها وأعمدتها بطريقة تراكمية عند بدء الخادم، ولا تمسح العملاء أو الطلبات.

```sh
docker compose build medusa-backend
docker compose build medusa-storefront
docker compose up -d --wait
docker compose --profile test build tests
docker compose --profile test run --rm tests node tests/unit-suites.cjs
docker compose --profile test run --rm tests node tests/publishing-upgrades.cjs
docker compose --profile test run --rm tests node tests/publishing-upgrades-ui.cjs
```

البناء والاختبارات الكبيرة بالتتابع على الأجهزة قليلة الذاكرة. تقارير الاختبارات ولقطات الواجهات تُحفظ محليًا تحت `scratch/docker-tests`؛ هذا المجلد لا يُرفع إلى Git.

ملف `.github/workflows/ci.yml` ينشئ أسرار اختبار عشوائية وبيئة فارغة، ويستخدم تهيئة متجر اختبار محمية بشرط `ALLOW_TEST_BOOTSTRAP=true` وعدم وجود عملاء أو طلبات. لا تشغّل هذا الإعداد على قاعدة الإنتاج ولا تستخدم `seed.ts` القديم لنقل بياناتك.

## برومبت لأي وكيل يكمل العمل

> اعمل داخل مستودع NOVEL_STOR على الفرع المحدد للمهمة. اقرأ OPERATIONS.md وdocs/PUBLISHING_WORKSPACE.ar.md وUPGRADE_IMPLEMENTATION.md، ثم افحص git status وDocker والخدمات قبل التعديل. الدفع مؤجل ولا تنفذ رسائل أو حملات خارجية. لا تعرض ملفات .env أو مفاتيح الوصول في المخرجات. خذ نسخة احتياطية دون استبدال البيانات. حافظ على الطلبات والعملاء والملفات ونسخ الكتب المنشورة، ولا تشغّل seed أو down -v على بيئة المستخدم. الصلاحيات تُفرض على الخادم، والمسودات لا تظهر في Store APIs قبل الاعتماد والنشر. استخدم عمال الاختبار المعزولين وبيانات اختبار موسومة ونظف بياناتهم فقط. نفّذ فحص الأنواع والوحدات ثم publishing-upgrades وpublishing-upgrades-ui واختبارات Medusa الأصلية المتأثرة، وشغّل البناء والاختبارات بالتتابع عند نقص الذاكرة. اختبر غياب الصلاحيات بعينات أدوار وجلسات حقيقية، وتزامن جهازين دون اتصال ومسح السجل، واستئناف رفع خاص، وعدم ظهور ملاحظات خاصة في التقارير. لا تعتبر نجاح صفحة الصحة دليلًا على نجاح الطلبات أو المسودات أو النشر. حدّث المستندات بنتائج ما اختُبر فعلًا، واذكر أي متطلبات نشر خارجية لم تُضبط، ثم ارفع التغييرات إلى الفرع المصرح به دون تعديل main أو رفع أسرار.
